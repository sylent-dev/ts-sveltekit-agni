# Technical choices

The stack, the commands and the main designs of Agni, each with its reason and its date. Every choice of a technology was presented to the owner as a grid (options, advantages, drawbacks, a score out of 10) and decided by them (`CLAUDE.md`, Communication); the grids of the setup (2026-11-22) are summed up here with their scores and the options set aside; the one still to confirm is given whole (PDF).

## Strictness of the code

`tsconfig.json` goes beyond `strict`, as in rust-ts-stepwise: `noUncheckedIndexedAccess` (`list[0]` and `table[key]` may be `undefined`), `noImplicitOverride`, `noImplicitReturns`, `noFallthroughCasesInSwitch`, `allowUnreachableCode: false`, `erasableSyntaxOnly` (no enum, no namespace, no parameter property), and `exactOptionalPropertyTypes` (a field left out is not a field set to `undefined`: tried at the setup as the owner chose on 2026-11-21, kept since the skeleton compiles with it; to look at again if Better Auth or Drizzle fight it, with the reason written here).

ESLint reads the types, for every file: `strictTypeChecked` and `stylisticTypeChecked` of typescript-eslint, and the rules that no set holds: `switch-exhaustiveness-check` (a `switch` without `default` names every value of its union), `no-unsafe-type-assertion`, `require-array-sort-compare`, `eqeqeq` (but for `== null`), and in a component `no-var` and `svelte/prefer-const`. Three rules are tuned, each with its reason in `eslint.config.js`. An exception is one line and its reason (`@eslint-community/eslint-plugin-eslint-comments`, and a selector in the markup); one that excuses nothing is an error (`reportUnusedDisableDirectives`), and so is a warning (`--max-warnings 0`). The types of Node.js are visible to every file of `src/` (one `tsconfig.json` for all: `svelte-check` reads one), so ESLint refuses `process`, `Buffer` and the other globals of Node.js, and the `node:` modules, in any file that may reach the browser (all of `src/` but `src/lib/server/`, the `*.server.ts` files, the tests and `src/env.ts`); the environment is read through `$app/env/private` or `$app/env/public` (review of step 0, 2026-11-22). The rules on the layout of the imports wait in the backlog.

## Errors

An expected failure is a `Result` (`src/lib/result.ts`): `{ ok: true, value }` or `{ ok: false, error }`, the error an object with a `code` that the route turns into a French text. A thrown error is a bug: `handleError` (`src/hooks.server.ts`) logs the route, the name of the error and the frames of its stack, never its message, which may quote what a user typed. Our own type of about fifteen lines rather than a library (`neverthrow`), as the owner chose on 2026-11-21.

## Tests

- **Unit tests**: Vitest, in two projects (`vite.config.ts`): `server`, in Node.js, for the `*.spec.ts` files; `client`, in Chromium through Playwright, for the `*.svelte.spec.ts` files of the components.
- **Tests in a browser**: Playwright (`playwright.config.ts`, `tests/*.e2e.ts`) on the production build served by `vite preview`, on a phone 360 px wide and on a computer. `tests/screens.e2e.ts` checks that every screen fits the width of the screen, is in French and logs no error, as `scripts/check-overflow.mjs` of idealan did, but inside Playwright Test rather than in a script of its own; the main path is added at step 9.
- The browser is installed once: `npx playwright install --only-shell chromium`.

## Dependencies

- Node.js 24 (`.nvmrc`, `engines`, `engine-strict=true` in `.npmrc`).
- npm 11 refuses the install scripts of the packages unless `allowScripts` in `package.json` allows them: `esbuild` is denied (its script only checks the binary that its optional package already brings).
- `npm audit --audit-level=high` runs in the CI, on every package: with `adapter-node`, the `devDependencies` (Svelte, SvelteKit, Drizzle) are bundled and run in production too, so `--omit=dev` would leave them out. On 2026-11-22, four moderate advisories concern `esbuild` through `drizzle-kit`, a tool of development only, which never runs in the application: accepted until drizzle-kit moves.
- Dependabot opens one pull request a month per ecosystem (npm, GitHub Actions); its security updates come apart, as soon as an advisory is published. The actions are pinned to a commit, their version in a comment (`.github/scripts/pinned-actions.sh`).

## Commands

| Command                              | What it does                                                                                                                         |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| `npm run dev`                        | The application in development, on `http://localhost:5173`.                                                                          |
| `npm run check`                      | Everything the CI checks: `format:check`, `check:types`, `lint`, `test:unit`, `test:e2e` (which builds the application first, once). |
| `npm run format`                     | Formats every file with Prettier.                                                                                                    |
| `npm run check:types`                | `svelte-check`, warnings included.                                                                                                   |
| `npm run lint`                       | ESLint and Stylelint, no warning allowed.                                                                                            |
| `npm run test:unit`                  | Vitest, once.                                                                                                                        |
| `npm run test:e2e`                   | Playwright, on a production build it makes first.                                                                                    |
| `npm run build`                      | The production build alone.                                                                                                          |
| `npm run db:generate` / `db:migrate` | A migration from the schema, then applied. `db:push` applies the schema without a migration, in development only.                    |
| `npm run db:studio`                  | Drizzle Studio, to look at the database.                                                                                             |
| `python3 docs/mockups/serve.py 8774` | The mock-up, served without cache on the port of this project (8774).                                                                |

Copy `.env.example` to `.env` before the first run.
